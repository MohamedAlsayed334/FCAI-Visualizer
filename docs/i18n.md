# i18n (Internationalization)

AlgoVs ships Arabic-first RTL + English UI via **i18next + react-i18next**, with
lazy per-locale namespace bundles (Vite `import.meta.glob`). Algorithm logic and
canvas drawing are untouched — translation is a data layer over the existing
Step contract.

## How it fits together

```
src/i18n/
  config.js        locale auto-discovery (locales/<code>/meta.json), registry,
                   resolution order: ?lang= URL → localStorage (fcai_visualizer_
                   locale) → navigator.languages → default 'en'
  i18n.js          i18next instance; lazy JSON loading via resourcesToBackend
  LocaleContext.js React context (locale, meta, isRTL, digits, setLocale…)
  LocaleProvider   <html lang|dir>, --font-locale, localStorage + URL sync,
                   preloads the bundle, then mounts children (no key flash)
  format.js        Intl number/date/time honoring the digits preference
  stepText.js      Step narration helpers (stepText / eventExplanation / eventOperation)
  exists.js        hasTranslation()

src/i18n/locales/<code>/   one JSON per namespace + meta.json config file

src/hooks/useLocale.js   context hook (UI locale) — distinct from useLang (code-language)
src/hooks/useT.js        t() hook scoped to a namespace
```

## Rules

1. **`useT(ns)` for page/panel chrome.** Keys live in that namespace; cross
   namespace calls use a **key prefix** — `t('algorithms:bubble.name')` — not
   an options object.
2. **Steps carry data, not prose.** Generators emit
   `msg` (legacy English fallback) **plus** `msgKey`/`msgParams` (see
   `sortingGenerators.js`, `searchingGenerators.js`, and the application
   DS/graph strategies). At display time, prefer `stepText(step)` /
   `eventExplanation(event)` / `eventOperation(event)`, which translate the key
   and fall back to the literal string. En templates in `steps.json` mirror the
   legacy `msg` byte-for-byte, so nothing changes visually in English.
3. **Keep in English inside Arabic copy:** algorithm **names**, Big-O notation,
   code identifiers/keywords, technical tags (LIFO, Push/Pop, BFS, lo/hi/mid,
   pivots, `a[i]` markers). Index pairs like `a[{{i}}]` stay Latin inside RTL
   strings — they render inline fine.
4. **Arabic plural completeness:** every key where en uses one/other gets all
   six Arabic categories (`zero/one/two/few/many/other`). `scripts/i18n-check.mjs`
   enforces this (`npm run i18n:check`).
5. **Fallback quiz bank + canvas math markers stay English** by design (content
   that mirrors course material / technical canvas annotations).
6. All `localStorage` keys are `fcai_visualizer_*`, always try/catch-wrapped.

## Plurals & placeholders

Use i18next plural suffixes (en needs `_one`/`_other`; ar all six) and `{{param}}`
interpolation. Example:

```json
"answered_one": "You answered {{count}} question",
"answered_other": "You answered {{count}} questions"
```

The nested object form (`{ "one": …, "other": … }`) is **not** supported by
i18next v26 — it resolves to the object instead of a string and the UI prints
the key. `npm run i18n:check` rejects it.

Calling `t('quiz.results.answered', { count: questionNumber })` picks the right
form via the active language. `steps:…` templates interpolate values directly.

## Digits

Western (`latn`) digits are the default everywhere, including Arabic. A separate
`fcai_visualizer_digits` preference (`latn`/`arab`) feeds `Intl` through
`format.js`. Canvas technical numbers stay Western manually.

## RTL

- Base direction flips via `<html dir="rtl">` set in `LocaleProvider`.
- Flex/text order follow `direction` automatically.
- Physical CSS that must mirror uses **logical properties**
  (`border-inline-end`, `inset-inline-end`, `padding-inline-start`) — see
  `Sidebar.css`.
- Directional icon glyphs get the `.rtl-flip` utility (`transform: scaleX(-1)`).
- `.ltr-keep` isolates Latin technical runs inside RTL prose.

## Adding a locale

1. Create `src/i18n/locales/<code>/` with `meta.json` (`name`, `nativeName`,
   `dir`, optional `fontFamily`, `defaultNumberingSystem`) + one JSON per
   namespace (copy `en` as the key skeleton).
2. Run `npm run i18n:check` until green, `npm run typecheck`, `npm run lint`,
   `npm run build`.
3. The switcher, `<html>` setup, font loading and routes pick it up with zero
   code changes.

## Commands

```
npm run i18n:check   # key parity, plural completeness, placeholder match
npm run typecheck    # tsc, scoped checkJs over src/i18n + src/hooks (tsconfig.json)
npm run verify       # lint + typecheck + i18n:check + build
```
